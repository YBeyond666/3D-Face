# SMIRK和DECA双数据集实验操作手册

本手册对应已交付的 face_reconstruction_benchmark v0.1 代码包，面向 Windows 电脑、单张 RTX 5080 的运行场景。按“环境准备 → 预训练推理 → 数据准备 → 四组短训练 → 正式实验 → 三维评价”的顺序操作。

当前自采数据 A 正在采集，Multiface B 尚未下载。现在可以先完成环境信息检查、模型环境配置和 Multiface mini 的接入及推理。四组训练需要 A、B 的训练与验证清单；三维评价还需要实际点位、标定和固定对应关系。

初版已通过28项本地检查，覆盖数据组织、实际生成的MP4读取、数值评价以及小型CPU网络的训练恢复。SMIRK、DECA本体与RTX 5080环境仍待实机验证。安装脚本是候选方案，出现错误时保留日志并在该步骤排查。

## 一 操作前先明确目录和终端

建议将代码包解压为以下目录。后文以此为例；实际放在其他盘符时，替换对应路径。

```text
D:\FaceBench\face_reconstruction_benchmark\
  README.md
  configs\
  environments\
  scripts\
  src\
  tests\
```

Windows PowerShell用于环境信息采集和安装WSL。Ubuntu终端用于安装Python环境、预处理、推理、训练及评价。两种终端的路径和续行符不同，命令不要混用。

| 环境 | 项目目录示例 | 命令使用位置 |
| --- | --- | --- |
| Windows | D:\FaceBench\face_reconstruction_benchmark | PowerShell |
| WSL中访问D盘 | /mnt/d/FaceBench/face_reconstruction_benchmark | Ubuntu终端 |
| 本手册采用的运行目录 | ~/face_reconstruction_benchmark | Ubuntu终端 |

后文除明确标注“PowerShell”的段落，其余命令均在Ubuntu项目根目录执行。Bash中的行末反斜杠表示下一行属于同一条命令；不要复制终端提示符。JSON里的null表示尚未填写，路径字符串要保留双引号。

## 二 收集Windows电脑环境信息

在普通PowerShell中执行：

```powershell
cd D:\FaceBench\face_reconstruction_benchmark
powershell -ExecutionPolicy Bypass -File .\environments\检查Windows环境.ps1
```

输出文件：outputs/environment/windows.json。检查其中是否识别到RTX 5080、GPU显存、驱动、WSL版本及磁盘剩余空间。用户先前报告的64 GB需要与GPU显存分开看，该脚本会分别采集。

本步骤完成标准：生成可打开的JSON报告。没有安装WSL也可以先完成这一步；WSL项报错本身不代表整个信息采集失败。若后续需要协助排查，首先提供该报告。

## 三 准备WSL和CUDA编译工具

### 1 安装或检查Ubuntu

已有正常运行的WSL2 Ubuntu时先检查版本；本手册的基础安装命令按Ubuntu 22.04编写。其他发行版不要直接混用Python和CUDA安装命令。

首次安装时，在管理员PowerShell中执行：

```powershell
wsl --install -d Ubuntu-22.04
wsl --update
wsl --list --verbose
```

按系统提示完成重启和Ubuntu账户初始化。检查发行版对应的VERSION为2；若为1，按实际发行版名称转换：

```powershell
wsl --set-version Ubuntu-22.04 2
```

以上命令参考[Microsoft WSL安装说明](https://learn.microsoft.com/en-us/windows/wsl/install)。Ubuntu用户名和密码是本机系统账户，无需发送给其他人。

### 2 将工程放入Ubuntu运行目录

打开Ubuntu终端。首次复制工程时执行：

```bash
cp -r /mnt/d/FaceBench/face_reconstruction_benchmark \
  ~/face_reconstruction_benchmark
cd ~/face_reconstruction_benchmark
pwd
ls
```

应能看到README.md、configs、environments、scripts和src。以后重新打开终端，只需进入该目录，不必重复复制。大体量数据可以留在其他磁盘，用/mnt/d等WSL路径引用；模型环境和代码在此目录维护。

### 3 准备基础工具并检查GPU

在Ubuntu 22.04中执行：

```bash
sudo apt update
sudo apt install -y python3.10 python3.10-venv python3.10-dev \
  build-essential git wget unzip libgl1 libglib2.0-0
python3.10 --version
nvidia-smi
```

完成标准：Python版本为3.10系列；Ubuntu里的nvidia-smi能识别显卡。若Windows能识别GPU而Ubuntu不能，应先排查Windows驱动与WSL状态，不要继续安装模型。

CUDA驱动由Windows提供；本工程编译PyTorch3D另外需要Ubuntu里的CUDA Toolkit。nvidia-smi显示的CUDA版本不等于已经安装了nvcc。WSL中不要再安装Linux显示驱动。[NVIDIA WSL指南](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)

### 4 准备CUDA编译工具

先检查已有工具链：

```bash
nvcc --version
```

若尚未安装，在WSL Ubuntu中按CUDA 12.8归档指南安装工具链。以下使用WSL软件源和指定的toolkit包：

```bash
wget https://developer.download.nvidia.com/compute/cuda/repos/wsl-ubuntu/x86_64/cuda-keyring_1.1-1_all.deb
sudo dpkg -i cuda-keyring_1.1-1_all.deb
sudo apt-get update
sudo apt-get install -y cuda-toolkit-12-8
export CUDA_HOME=/usr/local/cuda-12.8
export PATH="$CUDA_HOME/bin:$PATH"
export LD_LIBRARY_PATH="$CUDA_HOME/lib64:${LD_LIBRARY_PATH:-}"
nvcc --version
```

上述export只作用于当前终端。后续新开终端时需重新设置，或将三条export配置到自己的shell启动文件。软件源和包名应以[NVIDIA CUDA 12.8安装指南](https://docs.nvidia.com/cuda/archive/12.8.0/cuda-installation-guide-linux/index.html)为准；若包不可用，保留错误信息排查，不要随意改装其他CUDA大版本。

完成标准：nvcc显示12.8，且CUDA_HOME指向同一套工具链。驱动、Toolkit和PyTorch自带运行库属于不同层，分别检查。

## 四 安装两个模型的独立环境

### 1 执行候选安装脚本

回到Ubuntu项目根目录，先安装SMIRK：

```bash
cd ~/face_reconstruction_benchmark
mkdir -p outputs/environment
set -o pipefail
bash environments/bootstrap_wsl.sh smirk 2>&1 \
  | tee outputs/environment/install-smirk.log
```

通过后再安装DECA：

```bash
bash environments/bootstrap_wsl.sh deca 2>&1 \
  | tee outputs/environment/install-deca.log
```

脚本会建立.venv-smirk和.venv-deca，安装PyTorch 2.7.1及CUDA 12.8候选依赖、克隆固定版本上游代码，并从源码编译PyTorch3D。该组合仍需在5080实测；编译失败时先处理日志中的第一处错误，不要连续重复安装所有依赖。

### 2 激活环境并验收

```bash
source .venv-smirk/bin/activate
python -m facebench doctor --render-test --require-cuda \
  --out outputs/environment/smirk.json
```

切换到DECA时执行：

```bash
deactivate
source .venv-deca/bin/activate
python -m facebench doctor --render-test --require-cuda \
  --out outputs/environment/deca.json
```

检查两份报告中cuda_ready为true，renderer.ok为true，renderer.device为cuda。doctor检查的是GPU张量运算和简单网格渲染梯度；它不会加载完整SMIRK或DECA，因此还需完成后面的模型推理和短训练。

每次新开Ubuntu终端，都要先cd到项目目录并激活对应环境。模型资产下载、预处理或运行时也要确认当前环境；输入which python可以查看实际解释器路径。

## 五 准备模型权重和辅助资产

代码包不包含模型权重、FLAME或数据集。环境安装完成不代表下列文件已经齐全。按各项目官方入口取得相应授权并下载，保持文件名和目录结构。

| 用途 | 关键文件或资源 | 初版需要的阶段 |
| --- | --- | --- |
| SMIRK几何 | third_party/smirk/assets/FLAME2020/generic_model.pkl | 推理和训练 |
| SMIRK权重 | third_party/smirk/pretrained_models/SMIRK_em1.pt | 推理和微调初始化 |
| 二维预处理 | third_party/smirk/assets/face_landmarker.task；FAN模型 | 两来源图像预处理 |
| SMIRK训练 | assets/expression_templates_famos目录；VGG感知模型 | 双路径训练 |
| DECA几何 | third_party/deca/data/generic_model.pkl | 推理和训练 |
| DECA权重 | third_party/deca/data/deca_model.tar | 推理和微调初始化 |
| DECA纹理 | third_party/deca/data/FLAME_albedo_from_BFM.npz | 默认纹理渲染与训练 |
| DECA身份损失 | third_party/deca/data/resnet50_ft_weight.pkl | coarse训练 |

FLAME注册与许可见[官方入口](https://flame.is.tue.mpg.de/)。DECA纹理按[BFM转换工具](https://github.com/TimoBolkart/BFM_to_FLAME)准备，身份模型按[DECA训练说明](https://github.com/yfeng95/DECA#training)准备。仓库已带的UV、网格模板、嵌入和掩码也要保留，不能只复制一个权重文件运行。

SMIRK权重、MediaPipe资产及表情模板的操作参考[官方安装脚本](https://github.com/georgeretsi/smirk/blob/main/quick_install.sh)。该脚本还会询问EMOCA注册状态并下载额外辅助资源；只有满足对应条件时才执行相应流程。本初版配置关闭额外emotion_loss和mica_loss，这不意味着完整官方脚本会自动跳过这些下载。

旧格式官方权重在新版PyTorch中可能遇到weights_only加载错误。确认来源可信后，可将本机配置中的trusted_legacy_assets设为true，使上游调用兼容旧加载方式；其他报错仍按实际缺失文件排查。

完成标准：主要权重和所需资产位于对应目录，下载的ZIP已按说明解压。FAN、timm骨干或VGG资源首次使用时可能还会联网下载，请保留缓存和日志。

## 六 接入Multiface并先做预训练推理

### 1 下载mini并建立索引

激活SMIRK环境，在项目根目录执行：

```bash
git clone https://github.com/facebookresearch/multiface \
  third_party/multiface
python -m pip install requests==2.28.0 BeautifulSoup4==4.11.1
mkdir -p data/raw/multiface-mini
python scripts/download_multiface_mini.py \
  --repository third_party/multiface \
  --destination data/raw/multiface-mini
python -m facebench index-multiface \
  --root data/raw/multiface-mini \
  --out data/multiface/raw.jsonl --frame-step 3
```

下载器调用wget、tar和md5sum，需在Ubuntu执行。已经克隆仓库时跳过git clone。mini约16.2 GB；解压、预处理和模型缓存还会增加空间占用，开始前检查df -h。下载依据[Multiface官方说明](https://github.com/facebookresearch/multiface)。

frame-step 3表示对每个机位排序后的图像每3张取一张，不代表已经获得精确的100毫秒时间间隔。若暂时只接入某个机位，可在index-multiface命令中增加--cameras及实际机位目录名。

### 2 提取二维辅助标注并审计

```bash
python -m facebench preprocess \
  --manifest data/multiface/raw.jsonl \
  --out data/multiface/preprocessed \
  --mediapipe-asset third_party/smirk/assets/face_landmarker.task \
  --device cuda:0
python -m facebench audit \
  --manifest data/multiface/preprocessed/accepted.jsonl \
  --require-aux --out outputs/multiface-audit.json
```

输出accepted.jsonl、failures.jsonl及每张图像的辅助NPZ。完成标准：accepted数量大于0；audit报告ok为true；检查失败原因与比例。初版使用面部凸包掩码，不是精细皮肤分割，正式报告需说明该适配选择。

官方mini配置只有人物6795937和两个表情，不能直接划分未见人物训练、验证、测试集。当前用它检查预处理和推理，正式训练前另下载多人物子集。[官方mini配置](https://github.com/facebookresearch/multiface/blob/main/mini_download_config.json)

### 3 生成配置并运行两模型预训练参考

```bash
cp configs/local.example.json configs/local.json
python -m facebench plan --local configs/local.json \
  --out configs/smoke --seeds 17
```

检查local.json里的模型目录与权重位置。此时A的数据还没准备好，可以先保留A训练和共同验证清单的计划路径；plan只生成配置，infer不会读取训练与验证数据。check-run和train则要求这些清单真实存在，暂不执行。

SMIRK预训练推理：

```bash
python -m facebench infer \
  --config configs/smoke/smirk_multiface_s17.json \
  --manifest data/multiface/preprocessed/accepted.jsonl \
  --out outputs/predictions/pretrained_smirk_mini
```

切换DECA环境后运行：

```bash
deactivate
source .venv-deca/bin/activate
python -m facebench infer \
  --config configs/smoke/deca_multiface_s17.json \
  --manifest data/multiface/preprocessed/accepted.jsonl \
  --out outputs/predictions/pretrained_deca_mini
```

省略--checkpoint时使用配置中的官方预训练权重。输出包括predictions.jsonl、failures.jsonl、summary.json，以及逐帧网格NPZ和三联预览JPG。三联图从左到右为输入、渲染和叠加。先检查面部裁剪、朝向、口型和失败数量，再判断推理是否通过；程序运行结束不代表每帧都成功。

输出目录必须为空或不存在。重复试验请使用新的目录名，不要覆盖已生成结果。

## 七 接入自采数据并准备正式划分

### 1 填写session说明

```bash
cp configs/own_session.example.json \
  configs/own_session.local.json
```

使用编辑器修改JSON。每段录像在sessions数组中有一条记录；同一人物跨机位、跨session保持同一subject_id。以下路径均相对这份JSON所在的configs目录解析。

| 字段 | 应填写的实际内容 |
| --- | --- |
| subject_id与session_id | 人物编号与采集session编号 |
| sequence_id与camera_id | 动作或片段编号与机位编号 |
| video_path | 实际RGB视频，例如../data/raw/own/S001/session_001/rgb.mp4 |
| frame_count与frame_step | 帧数可为null交由视频读取；抽帧步长必须为正整数 |
| timestamps_path | 每帧原始时间记录文件，不是人为生成的固定帧率表 |
| timestamp_stream | 时间记录中RGB流的实际名称，例如rgb |
| timestamp_value_key | 记录中的时间字段，例如device_ts_ms |
| timestamp_to_seconds | 时间为毫秒时填0.001，秒时填1 |
| timestamp_index_key | 有明确帧号时填字段名；null表示筛选后的记录顺序作为帧索引 |
| clock_domain | 实际时钟域，不能保留REPLACE占位文字 |
| points_path与calibration_path | 原始人脸点位、标定文件；尚未准备时可为null |
| points_rgb_index_key | 点位记录中对应RGB索引的字段路径，例如source_indices.rgb |
| points_unit与coordinate_frame | 经核对的单位和坐标系名称 |
| point_id_mapping | 经核对的轨迹编号到物理F编号对应表；不确定时留空 |

F01至F32是人脸物理点编号，程序的数字track ID不能按顺序自动替换。原始markers与显示用插值或平滑结果应分开保存。当前模板对应旧采集代码已核查的结构，实际版本不同则先提供字段样例修改读取适配，不能靠猜测填写。

### 2 索引和预处理

```bash
python -m facebench index-own \
  --spec configs/own_session.local.json \
  --out data/own/raw.jsonl
python -m facebench preprocess \
  --manifest data/own/raw.jsonl --out data/own/preprocessed \
  --mediapipe-asset third_party/smirk/assets/face_landmarker.task \
  --device cuda:0
python -m facebench audit \
  --manifest data/own/preprocessed/accepted.jsonl \
  --require-aux --out outputs/own-audit.json
```

RGB训练接入可以先不带三维点位；但后续三维计分必须补齐点位和坐标对应。audit同时报告时间记录、点位与网格引用的样本数，用于确认哪些资产已经接入。

### 3 按人物划分和匹配预算

正式Multiface子集下载后，重新索引、预处理。不要用mini的单个人物清单冒充正式子集。以下划分只适用于A有10人、B有13人的示例，实际人数不同必须修改三个数字：

```bash
python -m facebench split \
  --manifest data/own/preprocessed/accepted.jsonl \
  --out data/own/split --counts 6 2 2
python -m facebench split \
  --manifest data/multiface/preprocessed/accepted.jsonl \
  --out data/multiface/split --counts 9 2 2
```

三个数字依次为train、val、test人数，总和必须等于清单中的身份总数。每组人数至少1，因而单个人物不能完成这种划分。检查输出split.json中的人数和样本量。

若两边各有至少6个训练人物且每人至少1000帧，可用以下示例建立相同预算；否则修改为双方均能提供的数量：

```bash
python -m facebench subset \
  --manifest data/own/split/train.jsonl \
  --subjects 6 --frames-per-subject 1000 --seed 17 \
  --out data/own/train_budget.jsonl
python -m facebench subset \
  --manifest data/multiface/split/train.jsonl \
  --subjects 6 --frames-per-subject 1000 --seed 17 \
  --out data/multiface/train_budget.jsonl
python -m facebench merge \
  --manifests data/own/split/val.jsonl \
    data/multiface/split/val.jsonl \
  --out data/common_val.jsonl
```

subset匹配的是人物与记录帧数，不自动匹配表情分布、时长或相邻帧冗余；正式协议另行固定这些规则。此处可让不同训练种子使用同一份预算子集，先隔离训练随机性的影响。

## 八 完成四组短训练

### 1 检查本机配置

编辑configs/local.json，将sources.own.train_manifest设为../data/own/train_budget.jsonl，sources.multiface.train_manifest设为../data/multiface/train_budget.jsonl，共同验证路径为../data/common_val.jsonl。没有使用预算子集时才保留原split/train.jsonl。

| 参数 | 初版示例 | 操作说明 |
| --- | --- | --- |
| max_steps | 100 | 用于流程检查，不能据此认定训练已充分收敛 |
| batch_subjects | 1 | 单卡起步值；每模型内部A和B使用相同设置 |
| deca_images_per_subject | 2 | DECA每个人物取2张，构成同人图像组 |
| save_every与val_every | 50与50 | 保存和验证间隔，均按训练步数 |
| max_val_per_subject | 8 | 每个验证人物固定选8帧，正式协议再冻结 |
| output_root | ../outputs/smoke | 建议与正式实验分开，避免覆盖 |

SMIRK输入batch为batch_subjects张图；DECA实际输入图像数为batch_subjects乘deca_images_per_subject。SMIRK循环路径将批次划为四类扰动，batch为1时覆盖不足，仅适合起步检查；正式batch结合显存测试再设定。初版没有梯度累积。

路径填完后重新生成，修改local.json不会自动改写已生成配置：

```bash
python -m facebench plan --local configs/local.json \
  --out configs/smoke --seeds 17
```

### 2 SMIRK两组

激活.venv-smirk，依次执行：

```bash
python -m facebench check-run \
  --config configs/smoke/smirk_own_s17.json
python -m facebench train \
  --config configs/smoke/smirk_own_s17.json
python -m facebench check-run \
  --config configs/smoke/smirk_multiface_s17.json
python -m facebench train \
  --config configs/smoke/smirk_multiface_s17.json
```

### 3 DECA两组

切换.venv-deca，依次执行：

```bash
python -m facebench check-run \
  --config configs/smoke/deca_own_s17.json
python -m facebench train \
  --config configs/smoke/deca_own_s17.json
python -m facebench check-run \
  --config configs/smoke/deca_multiface_s17.json
python -m facebench train \
  --config configs/smoke/deca_multiface_s17.json
```

DECA初版仅支持coarse训练，不能在本配置中切换为detail。check-run主要检查清单、人物隔离、同人采样数量、上游版本和初始权重；完整资产是否可加载仍要通过train验证。

### 4 检查输出并恢复中断

| 输出文件 | 检查内容 |
| --- | --- |
| run.json | status为completed，completed_steps达到设定步数 |
| effective_upstream_config.txt | 保存实际生效的上游配置 |
| metrics.jsonl | 有有限数值的损失、采样ID和验证记录 |
| validation_selection.jsonl | 固定的验证帧清单 |
| last.pt | 最近一次保存的完整训练状态 |
| best.pt | 按验证指标选出的状态 |

初版选模指标是共同验证集的二维关键点MAE，按人物和数据来源汇总；它不是三维重建误差。损失不保证每步下降，应检查数值有限、流程完整、输出合理。记录实际耗时与显存后再确定正式预算。

例如output_root为../outputs/smoke，恢复SMIRK自采组：

```bash
python -m facebench train \
  --config configs/smoke/smirk_own_s17.json \
  --resume outputs/smoke/smirk_own_s17/last.pt
```

恢复使用原配置、原数据清单与原初始权重，程序会检查签名。更改预算或清单后应新建实验目录，不要强行恢复旧运行。last.pt只包含最近保存点，未保存步骤需要重跑。

## 九 扩展正式实验和交叉推理

四组短训练与模型输出均正常后，再固定正式训练人物、采样量、batch、总步数、验证策略及初始权重。将local.json中的output_root改为../outputs/formal，并填入经过验证的正式预算。不要直接把100步结果当作正式主结果。

```bash
python -m facebench plan --local configs/local.json \
  --out configs/formal --seeds 17 29 43
python scripts/run_plan.py configs/formal/plan.json
```

第二条只打印命令。检查确实是2模型乘2来源乘3种子，共12份配置，输出目录各不相同。确认后执行：

```bash
python scripts/run_plan.py configs/formal/plan.json --execute
```

调度脚本默认分别使用.venv-smirk、.venv-deca解释器，按顺序占用单张GPU，遇到失败停止。它不会自动跳过已完成目录；已有部分结果时，可用--model筛选或单独运行尚未完成的配置。

所有训练组分别评价同一份A-test与同一份B-test。以SMIRK自采训练、种子17为例：

```bash
source .venv-smirk/bin/activate
python -m facebench infer \
  --config configs/formal/smirk_own_s17.json \
  --checkpoint outputs/formal/smirk_own_s17/best.pt \
  --manifest data/own/split/test.jsonl \
  --out outputs/predictions/smirk_own_s17_A
python -m facebench infer \
  --config configs/formal/smirk_own_s17.json \
  --checkpoint outputs/formal/smirk_own_s17/best.pt \
  --manifest data/multiface/split/test.jsonl \
  --out outputs/predictions/smirk_own_s17_B
```

其余组替换模型、训练来源、种子与输出名。DECA切换到其环境。官方预训练参考省略--checkpoint并使用原始初始化配置，每个模型在每个测试集跑一次即可。

## 十 三维点位评价和结果导出

### 1 准备参考与固定对应

此阶段需要真实参考，不能仅凭MP4与点位示意图执行。应核验F编号、时间对应、单位、坐标系、中性校准段以及模型表面对应。原始模型网格标为model_native_unverified，不能直接解释成毫米世界坐标。

自采点位导出只支持当前已核查的markers[].xyz_mm结构；数字轨迹需在session说明中提供经核对的point_id_mapping。以下命令的rig必须替换为清单中真实、已核验的坐标系名称：

```bash
python -m facebench export-own-points \
  --manifest data/own/split/test.jsonl \
  --unit mm --coordinate-frame rig \
  --out data/reference/own_test
```

只从test清单导出计分参考，避免把训练人物一并纳入评价。生成reference.jsonl与点位NPZ。

复制configs/correspondence.example.json，分别建立SMIRK和DECA的固定表面对应。需要填写model、实际vertex_count、point_ids、triangle_vertex_indices、barycentric_weights、fixed_subject_transforms、output_unit、output_frame和calibration_source。只有核验后才将correspondence_reviewed改为true。

每个点的三个顶点索引和重心权重由真实标记到模型表面的对应确定；每个人物的4乘4变换来自固定校准。不得把模板中的空数组或单位矩阵当作完成标定，也不得为每个测试帧重新拟合变换后声称绝对精度。

同样填写evaluation_protocol.example.json副本。coordinate_reviewed只有完成核验后才设为true；success_threshold_mm的5毫米和timestamp_tolerance_s的1毫秒只是代码模板示例，应按实验协议确定。

### 2 转换预测并计分

```bash
python -m facebench project-points \
  --manifest outputs/predictions/smirk_own_s17_A/predictions.jsonl \
  --mapping configs/smirk_mapping.local.json \
  --out outputs/aligned/smirk_own_s17_A
python -m facebench evaluate \
  --reference data/reference/own_test/reference.jsonl \
  --predictions outputs/aligned/smirk_own_s17_A/predicted_points.jsonl \
  --protocol configs/evaluation_protocol.local.json \
  --out outputs/results/smirk_own_s17_A.json
```

Multiface的OBJ参考网格尚无自动转F32或稠密表面计分入口；要比较B-test三维误差，需先为其几何建立合适的共同评价适配。可以先完成B-test推理，不得将A点位对应直接套用在不同拓扑的B网格上。

### 3 阅读和汇总结果

| 字段 | 含义 |
| --- | --- |
| subject_macro_mean_error_mm | 先逐帧有效点平均，再对帧和人物汇总的误差 |
| subject_macro_coverage | 参考有效点中成功获得预测的比例 |
| subject_macro_success_rate | 将缺失预测计作失败后的阈值成功率 |
| subjects_without_scored_predictions | 完全没有可计分预测的人物数 |
| per_subject和per_frame | 人物及帧级明细，用于定位异常 |

mean_error可能因困难点预测缺失而下降，应与覆盖率和失败数一起报告。单位、时间或坐标不一致时，先修正对应，不要删除检查代码绕过。

```bash
python -m facebench summarize \
  --results outputs/results/smirk_own_s17_A.json \
    outputs/results/smirk_multiface_s17_A.json \
  --out outputs/results/comparison_A.csv
```

CSV可用Excel打开。初版summarize逐文件汇总，不自动解析文件名分组、计算三个种子的均值和标准差，也不自动执行显著性或非劣检验；这些分析需在结果齐全后按模型、训练来源与测试集分别补充。速度和局部位移目前提供Python函数，不会自动出现在evaluate命令的结果中。

## 十一 常见问题排查

| 问题或报错 | 优先检查 |
| --- | --- |
| No module named facebench | 是否进入项目、激活对应环境并执行pip install -e . |
| nvcc not found | Ubuntu内是否安装Toolkit，CUDA_HOME和PATH是否指向12.8 |
| CUDA unavailable或no kernel image | Windows驱动、WSL GPU可见性、PyTorch CUDA包及渲染扩展编译架构 |
| PyTorch3D编译失败 | install日志第一处错误、nvcc、GCC、PyTorch版本；保留完整日志 |
| FLAME或纹理文件找不到 | 文件是否真正解压到各模型要求的位置，不能只提供ZIP |
| weights_only加载错误 | 是否为可信官方旧权重；按说明启用兼容选项，不绕过其他错误 |
| mini无法split | mini只有1人，改为接入／推理检查；正式划分需多人物数据 |
| Counts sum或Insufficient subjects | 划分总人数是否匹配；每人帧数与同人K是否足够 |
| Cross-split leakage | 同一人物、别名或同一图像进入多个划分；修正清单 |
| Expected exactly one face | 是否无人、多人、严重侧脸或图像读取错误；查看failures.jsonl |
| Nonempty run directory | 新建输出目录，或用原配置和有效last.pt显式恢复 |
| signature mismatch | 是否改变配置、数据清单或初始化权重；变更后作为新实验 |
| 点位、单位或坐标检查失败 | 检查track到F编号、RGB对齐、mm单位和固定标定，不猜测补齐 |

遇到问题时，保留正在运行的命令、对应配置JSON、终端从第一处错误开始的日志，以及run.json或环境报告。不要发送账户密码。先解决当前步骤，再继续后面的实验。
